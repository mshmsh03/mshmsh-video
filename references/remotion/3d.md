# 3D in Remotion

Three.js and React Three Fiber inside a Remotion video through `@remotion/three`: the canvas, lighting, driving every move from the frame, and sequences inside a 3D scene. Read it before building a 3D or product-turning shot. What a 3D short should look like and how long it runs is in styles.md ("3D or simulation"); the 3D device tilt on a flat screenshot is plain CSS (production.md, `Laptop` and `Phone`). Everything else follows normal React Three Fiber and Three.js practice; only the rules below are Remotion's own.

## Setup

```bash
npx remotion add @remotion/three
```

With bun, yarn or pnpm: `bunx remotion add @remotion/three`, `yarn remotion add @remotion/three`, `pnpm exec remotion add @remotion/three`. It works with `three` and `@react-three/fiber`; install them too if the project doesn't have them.

## The canvas

All 3D content goes inside `<ThreeCanvas>` from `@remotion/three`, never React Three Fiber's own `<Canvas>`. It **must** get `width` and `height`; take them from `useVideoConfig()`. Add lights: a standard material with no light renders black.

```tsx
import { ThreeCanvas } from "@remotion/three";
import { interpolate, useCurrentFrame, useVideoConfig, Easing } from "remotion";

export const TurningCup = () => {
  const frame = useCurrentFrame();
  const { width, height, fps } = useVideoConfig();
  const turn = interpolate(frame, [0, 4 * fps], [0, Math.PI * 2]);
  const lift = interpolate(frame, [0, 0.8 * fps], [-1.2, 0], {
    extrapolateRight: "clamp",
    easing: Easing.bezier(0.16, 1, 0.3, 1),
  });

  return (
    <ThreeCanvas width={width} height={height} camera={{ position: [0, 1.2, 5], fov: 35 }}>
      <ambientLight intensity={0.35} />
      <directionalLight position={[3, 4, 5]} intensity={1.1} />
      <mesh position={[0, lift, 0]} rotation={[0.1, turn, 0]}>
        <cylinderGeometry args={[0.8, 0.65, 1.4, 48]} />
        <meshStandardMaterial color="#c8553d" roughness={0.45} />
      </mesh>
    </ThreeCanvas>
  );
};
```

## Every move comes from the frame

Remotion renders frames out of order and in parallel, so anything that animates on its own clock flickers or jumps in the render.

- **Never use `useFrame()` from `@react-three/fiber`.** It runs on the browser's clock, not Remotion's.
- Shaders, models, particle systems and animation mixers must not run by themselves. Drive them from `useCurrentFrame()`: a rotation from `interpolate(frame, ...)`, a shader `uniform` set from `frame / fps`, an animation clip's time set to `frame / fps` before each render.
- Randomness comes from `random(seed)` in `remotion`, as everywhere else (motion.md).

## Sequences inside the canvas

A `<Sequence>` used inside `<ThreeCanvas>` must have `layout="none"`. The default layout adds an HTML `<div>`, which can't exist inside a Three.js scene.

```tsx
<ThreeCanvas width={width} height={height}>
  <ambientLight intensity={0.4} />
  <Sequence from={1 * fps} layout="none">
    <Logo3D />
  </Sequence>
</ThreeCanvas>
```

Inside, `useCurrentFrame()` starts from 0 at the sequence's `from`, as in 2D.

## Rendering

3D uses WebGL, so renders need Chrome's GL turned on: `Config.setChromiumOpenGlRenderer("angle")` in `remotion.config.ts`, or `--gl=angle` on the render command (look-effects.md, "Turning on WebGL for renders"). On an integrated GPU, keep geometry and shadow maps modest and render a few stills of the busiest frame before the full video (review.md).
